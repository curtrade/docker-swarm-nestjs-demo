# Глава 12. Multi-node кластер на VM

> Тег шага: `step-12` · Часть 4 (capstone, multi-node)

## Цель

Поднять настоящий многоузловой Swarm — несколько VM (manager + worker'ы). До сих
пор всё было на одном узле; теперь появятся темы, которые на одной машине просто
не показать: распределение по узлам, отказ узла, кворум, обслуживание.

## Почему VM

На одном Docker-демоне «несколько узлов» не сделать. Поднимем лёгкие Ubuntu-VM
через **multipass** — это кросс-платформенно и скриптуемо.

## Поднятие кластера

Один скрипт делает всё (см. `deploy/vms/`):

```bash
bash deploy/vms/provision.sh            # 1 manager + 2 worker
```

Что внутри:

1. `multipass launch` создаёт VM, cloud-init ставит Docker.
2. На менеджере — `docker swarm init --advertise-addr <IP>`.
3. На всех узлах настраивается доверие к локальному registry (`insecure-registries`,
   понадобится в главе 13).
4. Worker'ы присоединяются по join-token:
   ```bash
   docker swarm join --token <worker-token> <MANAGER_IP>:2377
   ```

Проверка:

```bash
multipass exec swarm-manager -- docker node ls
# MANAGER STATUS Leader у одного, остальные — worker, все Ready
```

## Роли узлов

- **Manager** — хранит состояние кластера (Raft), принимает команды, планирует
  задачи. Менеджеров может быть несколько (кворум — глава 14).
- **Worker** — только выполняет задачи.

Один manager — точка отказа управления (кластер продолжит работать, но менять его
будет нельзя). О кворуме менеджеров — в главе 14.

## Где запускать команды

Дальше `docker stack deploy` и прочее выполняем **на менеджере**:

```bash
multipass shell swarm-manager
# либо
multipass exec swarm-manager -- docker ...
```

Файлы проекта на менеджер можно перенести через `multipass transfer` или git clone.

## Best practices и анти-паттерны

- ✅ **Скриптуемый провижининг** (cloud-init + provision.sh) — кластер
   воспроизводим, не «настроен руками».
- ✅ **`--advertise-addr`** с явным IP — на узле с несколькими интерфейсами Swarm
   иначе не угадает адрес.
- ❌ **Не** оставляй один manager в проде — потеря менеджера лишает кластер
   управления; нужно нечётное число (3/5).
